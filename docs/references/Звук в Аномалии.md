## 1. О документе

Это живой справочник по звуковой системе S.T.A.L.K.E.R.: Anomaly 1.5.1–1.5.3 для
разработки модов, прежде всего Sound Vision. Все факты проверены по
первоисточникам: исходникам движка Monolith (репозиторий
themrdemonized/xray-monolith, ветка all-in-one-vs2022-wpo), дампу базовых
скриптов Anomaly 1.5.x (xr_hear.script, xr_motivator.script, lua_help.script) и
гайду по моддингу robe127. Там, где факт взят из инструментов сообщества
(SAVandT/CACO), это указано явно.

Правило пополнения: каждый новый факт о звуке записывается сюда с указанием
источника (файл и репозиторий, либо ссылка). Если факт получен экспериментально
в игре — помечается «экспериментально». Спорные или не подтверждённые
утверждения не записываются. Так документ остаётся доверенным источником и не
превращается в сборник слухов.

Соглашение об именах: **max_distance** — аудио-дальность слышимости (громкое
«ухо» игрока), **max_ai_distance** — дальность слуха искусственного интеллекта
из ogg-комментария, **volume** — текущая громкость звука (0..1 и выше),
**Power** — итоговая громкость события у конкретного слушателя, посчитанная
движком.

## 2. Файловая структура звуков

Все звуки игры лежат в `gamedata/sounds/` в формате `.ogg` (Vorbis). Аддоны
добавляют или переопределяют файлы одноимёнными путями. В скриптах путь
указывается относительно папки `sounds`, без расширения; разделитель — двойной
обратный слэш или конструкция `[[...]]`.

**Таблица 2.1. Основные каталоги звуков**

| Каталог | Содержимое |
|---|---|
| `material\human\step\` | Шаги людей (NPC) по материалам: earth, grass, metal, wood, water и т.д. |
| `material\actor\step\` | Шаги самого актёра |
| `material\monster\`, `material\mutant\` | Шаги мутантов |
| `monsters\` | Голоса мутантов: рычание, атаки, смерть, поедание |
| `weapons\` | Выстрелы, перезарядка, пустые щелчки, handling |
| `device\`, `interface\` | Детекторы, КПК, фонари; UI и инвентарь |
| `ambient\`, `nature\`, `anomaly\` | Окружение, погода, аномалии |
| `characters_voice\` | Реплики сталкеров (диалоги, крики, стоны) |
| `actor\` | Дыхание, экипировка, headgear — звуки актёра |

Материал поверхности для шагов выбирается парой материалов (`SGameMtlPair`) из
level-геометрии и объекта; сами звуки шага задаются в паре материалов
(`StepSounds`), а громкость и тайминги — в конфиге анимаций (см. раздел 8).

## 3. Ogg-комментарии: метаданные звука

Источник: `src/xrSound/SoundRender_Source_loader.cpp` (xray-monolith). Движок
читает первый vorbis-комментарий файла как бинарную структуру: первые 4 байта —
версия (u32), затем поля подряд. Без корректного комментария звук не участвует
в ИИ-механиках должным образом; в режиме `-dbg` движок пишет «Missing
ogg-comment» или «Invalid ogg-comment version». Валидация: `max_ai_distance` и
`max_distance` должны быть не меньше 0.1, иначе `R_ASSERT` («Invalid max
distance»).

**Таблица 3.1. Поля ogg-комментария по версиям**

| Версия | Поля (порядок чтения) | Что выводится |
|---|---|---|
| 0x0001 | min_distance, max_distance, game_type (u32) | base_volume = 1.0; max_ai_distance = max_distance |
| 0x0002 | min_distance, max_distance, base_volume, game_type | max_ai_distance = max_distance |
| 0x0003 (актуальная) | min_distance, max_distance, base_volume, game_type, max_ai_distance | все поля независимы |

Смысл полей: **min_distance** — ближе этого расстояния громкость для игрока
полная; **max_distance** — дальше этого расстояния звук для игрока обрезается
(см. раздел 4); **base_volume** — громкость у источника; **game_type** — битовая
маска ESoundTypes (раздел 5), по ней ИИ классифицирует звук;
**max_ai_distance** — дальность, на которой ИИ вообще услышит звук.

Инструменты сообщества (не проверялись по исходникам): SAVandT (Sound Attribute
Viewer And Tweaker) — просмотр и правка комментариев в GUI; CACO — пакетная
постановка комментариев. Оба пишут версию 0x0003. Поле game_type в них
подписано как Game Sound Type со значениями вида weapon_shooting, NPC_step,
item_dropping — это те же биты ESoundTypes.

## 4. Модель громкости в движке

### 4.1. Слух ИИ: как рождается событие звука

Источник: `src/xrEngine/IGame_Level.cpp`, `SoundEvent_Register`. Каждый
играющий звук периодически рассылается слушателям: движок запрашивает все
объекты-слушатели (spatial-тип `STYPE_REACTTOSOUND`) в кубе вокруг звука с
полустороной `range` и для каждого считает громкость события:

```
Power  = (1 - dist / max_ai_distance) * volume
Power *= occlusion
```

где `dist` — расстояние от звука до слушателя, `volume` — текущая громкость
звука, `occlusion` — глушимость между источником и слушателем
(`Sound::get_occlusion_to`, SOM-геометрия). Слушатели дальше `max_ai_distance`
отсеиваются ещё до формулы; события с `Power` ниже EPS отбрасываются. Радиус
запроса: `range = min(max_ai_distance, max_ai_distance * volume)` — тихий звук
(volume < 1) ИИ слышит на пропорционально меньшем расстоянии. Ограничение range
сверху: 500 м.

Источник: `src/xrSound/SoundRender_Emitter.cpp`, `Event_Propagade`. Рассылка
происходит только если у звука задан game_type (`g_type != 0`) и привязан
игровой объект (`g_object != 0`); период повторной рассылки играющего звука —
`s_f_def_event_pulse = 0.5` с (SoundRender.h). Следствие: зацикленные и длинные
звуки (гул зоны, стрельба очередями) продолжают «заявлять о себе» каждые
полсекунды, а короткий одиночный выстрел — один раз.

### 4.2. Слух игрока: аудио-модель

Источник: `src/xrSound/SoundRender_Emitter_FSM.cpp`, `update_culling`. Для
слушателя-игрока движок считает итоговую громкость так: если
`dist > max_distance` — звук замолкает (cull); иначе громкость линейно падает
от `min_distance` до `max_distance`:

```
volume_att = (max_distance - dist) / (max_distance - min_distance)  -- clamp 0..volume
```

`smooth_volume = base_volume * volume_att *` мастер-громкость
эффектов/музыки `* occluder_volume` (глушимость между звуком и игроком; для
`world_ambient` принудительно 1.0) `* fade_volume`. Ниже порога `psSoundCull`
звук выкидывается из микса. Итого обе модели — ИИ и аудио — линейны по
расстоянию, но с разными пределами: у ИИ — `max_ai_distance` из комментария,
у аудио — `max_distance`.

### 4.3. Кто и что доходит до Lua

Источник: `src/xrGame/sound_memory_manager.cpp`, `feel_sound_new`. Сначала
вызывается скриптовый колбэк звука (`m_object->sound_callback`) — ДО любых
порогов восприятия ИИ, т.е. колбэк получает все события в радиусе, даже слабые.
Только после этого применяются факторы типа (weapon_factor, item_factor,
npc_factor, anomaly_factor, world_factor) и адаптивный порог
`m_sound_threshold` (затухает со временем к `m_min_sound_threshold`) — они
влияют лишь на память ИИ, не на колбэк.

Актёр (игрок) слушателем в Lua не отчитывается: `src/xrGame/Actor_Feel.cpp` —
`CActor::feel_sound_new` только запоминает собственный шум `m_snd_noise` (когда
источник — сам игрок). Поэтому моды «слышат» мир исключительно через уши NPC и
мутантов.

## 5. Типы звуков (ESoundTypes)

Источник: `src/xrServerEntities/ai_sounds.h` и экспорт в Lua (snd_type,
lua_help.script). Тип — битовая маска: старший бит задаёт класс
(оружие/предмет/монстр/аномалия/мир), младшие — характер звука.
Комбинированные значения заданы в заголовке явно (например,
`SOUND_TYPE_MONSTER_STEP = MONSTER | STEP`).

**Таблица 5.1. Биты классов и характеров звука**

| Бит | Значение | Смысл |
|---|---|---|
| WEAPON | 0x80000000 | оружие (выстрелы, перезарядка, щелчки) |
| ITEM | 0x40000000 | предметы (подбор, бросок, прятание) |
| MONSTER | 0x20000000 | мутанты (шаги, атаки, речь, смерть) |
| ANOMALY | 0x10000000 | аномалии (SOUND_TYPE_ANOMALY_IDLE = ANOMALY \| IDLE) |
| WORLD | 0x08000000 | мир: collide/break/explode/ambient |
| STEP | 0x00008000 | шаги (в паре с классом: MONSTER \| STEP) |
| TALKING | 0x00004000 | речь |
| SHOOTING | 0x00200000 | выстрел (WEAPON \| SHOOTING) |
| EMPTY_CLICKING | 0x00100000 | пустой щелчок |
| BULLET_HIT | 0x00080000 | попадание пули |
| RECHARGING | 0x00040000 | перезарядка |
| DYING / INJURING | 0x00020000 / 0x00010000 | смерть / ранение |
| ATTACKING / EATING | 0x00002000 / 0x00001000 | атака / поедание |
| IDLE | 0x00000800 | простой (гул аномалии) |
| OBJECT_BREAKING / COLLIDING / EXPLODING | 0x00000400 / 0x00000200 / 0x00000100 | поломка / столкновение / взрыв |

Для скриптов важны константы `snd_type.*` из lua_help.script:
`snd_type.weapon_shoot = -2145386496` (старший бит знаковый в Lua),
`snd_type.monster_step = 536903680`, `snd_type.item_drop = 1107296256` и т.д.
Проверка типа в Lua — битовая:
`bit_and(sound_type, snd_type.monster_step) == snd_type.monster_step`.

## 6. Lua API: sound_object и xr_sound

**sound_object** — скриптовый звук. Создаётся по пути без расширения:
`sound_object([[material\human\step\n_earth_01]])`. Флаги:
`sound_object.s3d = 0` (3D), `sound_object.s2d = 2` (2D «в голове»),
`sound_object.looped = 1`. Основные методы: `play(obj[, delay[, flags]])`,
`play_at_pos(obj, pos[, delay[, flags]])`,
`play_no_feedback(obj, flags, delay, pos, volume[, frequency])`, `stop()`,
`stop_deffered()`, `playing()`, `length()`; свойства `volume`, `frequency`,
`min_distance`, `max_distance`, `set_position`.

Важно: свойства громкости и дальностей читаются/меняются только у собственных
sound_object. Для движковых звуков (выстрелы, шаги, речь NPC) прочитать их
параметры из Lua нельзя — см. раздел 10. `play_no_feedback` создаёт эмиттер без
связи с исходным ref_sound и, что критично, шаги сталкеров играются именно так
(раздел 8).

**xr_sound** — обвязка схем: `get_safe_sound_object(path)` (безопасное
создание), `get_sound_object(theme, mode)`, `set_sound_play(id, theme, ...)`
для проигрывания реплик по sound-схемам; темы описываются в xml-конфигах схем
(sound_schemes).

## 7. Колбэки звука

### 7.1. npc_on_hear_callback — главная точка входа

Полная цепочка (все звенья проверены по исходникам): движок →
`CScriptEntity::sound_callback` (буферизация) →
`CScriptEntity::process_sound_callbacks` → колбэк `GameObject::eSound` →
motivator_binder:hear_callback / generic_object_binder:hear_callback
(xr_motivator.script и bind_monster.script: пропускают мёртвых слушателей и
самозвуки) → xr_hear.hear_callback →
`SendScriptCallback("npc_on_hear_callback", ...)`. Слушателями выступают все
сталкеры (xr_motivator) и мутанты (bind_monster).

Реальная сигнатура (по xr_hear.script):

```lua
npc_on_hear_callback(npc, who_id, s_type, sound_dist, sound_power, sound_position)
```

**Таблица 7.1. Параметры npc_on_hear_callback**

| Параметр | Тип | Семантика |
|---|---|---|
| `npc` | game_object | слушатель: NPC или мутант, который услышал звук |
| `who_id` | number | id объекта-источника звука |
| `s_type` | string | строка типа, вычисленная xr_hear из маски: WPN_shoot, WPN_empty, WPN_hit, WPN_reload, WPN_show, WPN_hide, ITM_pckup, ITM_drop, ITM_hide, ITM_take, ITM_use, MST_die, MST_damage, MST_step, MST_talk, MST_attack, MST_eat; без уточнения — WPN / ITM / MST; прочие маски — NIL |
| `sound_dist` | number | КВАДРАТ расстояния слушатель↔источник (distance_to_sqr!) — перед использованием извлекать корень |
| `sound_power` | number | громкость события у слушателя 0..1: уже учтены расстояние и стены (раздел 4.1) |
| `sound_position` | vector | позиция источника; для 2D-звука — позиция камеры |

В xr_hear.script также живёт механика on_sound строк логики (hear_sounds):
condlist срабатывает, когда слуховая дистанция и power превысят пороги из
схемы. Это удобный референс того, как сама игра фильтрует события по громкости.

### 7.2. Прочие колбэки

**Таблица 7.2. Колбэки, связанные со звуком (robe127 + исходники)**

| Колбэк | Сигнатура | Когда срабатывает |
|---|---|---|
| actor_on_footstep (ваниль) | (surface: string, power: number, is_crouching: boolean, flags: table) | шаг игрока; surface — имя материала; flags.ret_value = false отключает ванильный звук |
| actor_on_footstep (modded exes) | (obj: game_object, surface: number, ?, ?, ?) | низкоуровневый вариант на modded exes; первый параметр — объект |

Регистрация: `RegisterScriptCallback("имя", функция)` в `on_game_start`,
снятие — `UnregisterScriptCallback` в `on_game_end`. Названия колбэков
регистрируются через axr_main.script; каждый вызов RegisterScriptCallback
стоит оборачивать в pcall, чтобы на чужой сборке отсутствие колбэка не ломало
остальные.

## 8. Как устроены шаги

Источник: `src/xrGame/step_manager.cpp`. Шаги привязаны к анимациям: в конфиге
персонажа секция `step_params` перечисляет анимации движения; для каждой —
число циклов и на каждую ногу время и power (0..1) шага в цикле. При наступании
движок берёт пару материалов под ногой, играет случайный звук из StepSounds
пары и передаёт power дальше.

Ключевые факты: аудио шагов играется только в пределах
`g_step_sound_distance = 50` м от камеры (дальше — тишина, партиклы тоже
отключаются по `g_step_particle_distance = 50`); у актёра перед проигрыванием
вызывается Lua-функция `CActor__FootstepCallback(имя_материала, power,
hud_mode)` — тот самый actor_on_footstep; у NPC вызывается C++
`FootStepCallback(power, b_play_sound, is_on_ground, hud_mode)`. В hud-режиме
звук шага 2D с громкостью `power * psHUDStepSoundVolume`, в мире — 3D.

Шаги NPC играются через `play_no_feedback`: тип звука не задаётся, поэтому
Event_Propagade их не рассылает ИИ (`g_type == 0`) — до npc_on_hear_callback
шаги сталкеров НЕ доходят. Шаги мутантов доходят (MST_step): мутанты играют их
как обычные типизированные звуки. Для сталкеров единственный надёжный источник
— опрос мира по движению (так делает Sound Vision) либо modded exes.

Константы громкости из `src/xrServerEntities/ai_sounds.h`:
`CROUCH_SOUND_FACTOR = 0.3` и `ACCELERATED_SOUND_FACTOR = 0.5` — движковые
множители тихого и ускоренного движения; применяются при подсчёте
воспринимаемого шума персонажа. Практический вывод: крадущийся NPC втрое
«тише» идущего, ускоряющийся — вдвое громче.

## 9. Практические паттерны

### 9.1. Модель слышимости Sound Vision (якорь ИИ + обратный квадрат)

Задача: показывать кольцо только если игрок слышит звук, без калибровки каждого
.ogg. Решение v2.0: каждое событие npc_on_hear_callback — это «замер громкости»
чужим ухом. Громкость у игрока восстанавливается децибельной моделью
расхождения фронта (−6 дБ на удвоение расстояния):

```
loud = power * (dl / dp)^2    -- dl: дистанция ИИ-слушателя, dp: игрока
```

Показывать, если `loud >= порог` (MCM, по умолчанию 0.02) и `dp <= 150` м.

Свойства модели: если игрок ближе слушателя — громкость у него не меньше,
событие показывается всегда; стены уже «вшиты» в power (occlusion) и
дополнительно уменьшают loud; за пределами слуха ИИ событий не существует
вовсе, поэтому дальнее поле не спамит. Численный прогон (симуляция при пороге
0.02): выстрел из автомата виден до ~150 м (предел показа), крик — до ~80 м,
шаги бегущего — ~35 м, идущего — ~29 м, крадущегося — ~25 м, толкание бочки —
~20 м.

Источники без движковых данных (шаги сталкеров, физика, гул зон) несут
громкость от «виртуальных якорей»: константа `{d_v, p_v}` — на d_v метрах
громкость p_v, дальше тот же обратный квадрат. Шаги: p_v растёт со скоростью
движения, измеренной между опросами (крадущийся 0.10, бегущий 0.24 на якоре
10 м). Это 4 числа на все опрошенные источники — не калибровка каждого звука.

### 9.2. Слой поверх шагов актёра

```lua
local function actor_on_footstep(surface, power, is_crouching, flags)
    local vol = power * (is_crouching and 0.3 or 1.0)  -- как CROUCH_SOUND_FACTOR
    local snd = xr_sound.get_safe_sound_object("my_foley\\cloth_" .. math.random(1, 8))
    if snd then
        snd:play_no_feedback(db.actor, sound_object.s2d, 0, vector(), vol)
    end
end
RegisterScriptCallback("actor_on_footstep", actor_on_footstep)
```

### 9.3. Что читать, когда нужно «поймать» событие

Оружие и монстры — npc_on_hear_callback (типы `WPN_*`, `MST_*`): движок сам
отдаёт громкость и позицию. Собственные шаги игрока — actor_on_footstep
(surface, power). Движение/физика без ИИ-событий — только опрос (db.storage,
сравнение позиций по таймеру 4 Гц, как в sound_vision_detect.script). Аномалии
— anomaly_on_before_activate и actor_on_feeling_anomaly. Удары по объектам —
physic_object_on_hit_callback (amount пригоден как прокси громкости).

## 10. Ограничения и подводные камни

Проверено по исходникам:

1. из Lua нельзя прочитать параметры чужих звуков — base_volume, max_distance,
   max_ai_distance доступны только для собственных sound_object;
2. актёр не получает npc_on_hear_callback как слушатель — «слух игрока»
   недоступен напрямую, только через уши NPC;
3. шаги сталкеров не рассылаются ИИ (play_no_feedback, g_type = 0) — ловить
   движением;
4. sound_dist в колбэке — квадрат расстояния, не забывать корень;
5. рассылка повторяется каждые ~0.5 с — нужен антиспам;
6. 2D-звуки приходят с позицией камеры.

Из практики сообщества (экспериментально, не из исходников): глобального
«on_any_sound_played» нет; громкость многослойных звуков оружия правится только
заменой .ogg или sound_layers в LTX; sound_object нельзя создавать каждый кадр
— кэшировать; слух ИИ настраивается факторами в ltx (weapon_factor и др.), что
влияет на память ИИ, но не на колбэк.

| Сигнатура (npc, who_id, s_type, dist, sound_power, sound_position) | Верно с уточнением | Порядок верный; s_type — строка из xr_hear; dist — КВАДРАТ расстояния (distance_to_sqr) |
