## 1. О документе

Это живой справочник по звуковой системе S.T.A.L.K.E.R.: Anomaly 1.5.1–1.5.3 для
разработки модов, прежде всего Sound Vision. Все факты проверены по
первоисточникам: исходникам движка Monolith (репозиторий
themrdemonized/xray-monolith, ветка all-in-one-vs2022-wpo), дампу базовых
скриптов Anomaly 1.5.x (xr_hear.script, xr_motivator.script, lua_help.script) и
гайду по моддингу robe127. Там, где факт взят из инструментов сообщества
(SAVandT/CACO), это указано явно.

Правило пополнения: каждый новый факт о звуке записывается сюда с указанием
источника (файл и репозиторий, либо ссылка). Если факт получен экспериментально
в игре — помечается «экспериментально». Спорные или не подтверждённые
утверждения не записываются. Так документ остаётся доверенным источником и не
превращается в сборник слухов.

Соглашение об именах: **max_distance** — аудио-дальность слышимости (громкое
«ухо» игрока), **max_ai_distance** — дальность слуха искусственного интеллекта
из ogg-комментария, **volume** — текущая громкость звука (0..1 и выше),
**Power** — итоговая громкость события у конкретного слушателя, посчитанная
движком.

## 2. Файловая структура звуков

Все звуки игры лежат в `gamedata/sounds/` в формате `.ogg` (Vorbis). Аддоны
добавляют или переопределяют файлы одноимёнными путями. В скриптах путь
указывается относительно папки `sounds`, без расширения; разделитель — двойной
обратный слэш или конструкция `[[...]]`.

**Таблица 2.1. Основные каталоги звуков**

| Каталог | Содержимое |
|---|---|
| `material\human\step\` | Шаги людей (NPC) по материалам: earth, grass, metal, wood, water и т.д. |
| `material\actor\step\` | Шаги самого актёра |
| `material\monster\`, `material\mutant\` | Шаги мутантов |
| `monsters\` | Голоса мутантов: рычание, атаки, смерть, поедание |
| `weapons\` | Выстрелы, перезарядка, пустые щелчки, handling |
| `device\`, `interface\` | Детекторы, КПК, фонари; UI и инвентарь |
| `ambient\`, `nature\`, `anomaly\` | Окружение, погода, аномалии |
| `characters_voice\` | Реплики сталкеров (диалоги, крики, стоны) |
| `actor\` | Дыхание, экипировка, headgear — звуки актёра |

Материал поверхности для шагов выбирается парой материалов (`SGameMtlPair`) из
level-геометрии и объекта; сами звуки шага задаются в паре материалов
(`StepSounds`), а громкость и тайминги — в конфиге анимаций (см. раздел 8).

## 3. Ogg-комментарии: метаданные звука

Источник: `src/xrSound/SoundRender_Source_loader.cpp` (xray-monolith). Движок
читает первый vorbis-комментарий файла как бинарную структуру: первые 4 байта —
версия (u32), затем поля подряд. Без корректного комментария звук не участвует
в ИИ-механиках должным образом; в режиме `-dbg` движок пишет «Missing
ogg-comment» или «Invalid ogg-comment version». Валидация: `max_ai_distance` и
`max_distance` должны быть не меньше 0.1, иначе `R_ASSERT` («Invalid max
distance»).

**Таблица 3.1. Поля ogg-комментария по версиям**

| Версия | Поля (порядок чтения) | Что выводится |
|---|---|---|
| 0x0001 | min_distance, max_distance, game_type (u32) | base_volume = 1.0; max_ai_distance = max_distance |
| 0x0002 | min_distance, max_distance, base_volume, game_type | max_ai_distance = max_distance |
| 0x0003 (актуальная) | min_distance, max_distance, base_volume, game_type, max_ai_distance | все поля независимы |

Смысл полей: **min_distance** — ближе этого расстояния громкость для игрока
полная; **max_distance** — дальше этого расстояния звук для игрока обрезается
(см. раздел 4); **base_volume** — громкость у источника; **game_type** — битовая
маска ESoundTypes (раздел 5), по ней ИИ классифицирует звук;
**max_ai_distance** — дальность, на которой ИИ вообще услышит звук.

Инструменты сообщества (не проверялись по исходникам): SAVandT (Sound Attribute
Viewer And Tweaker) — просмотр и правка комментариев в GUI; CACO — пакетная
постановка комментариев. Оба пишут версию 0x0003. Поле game_type в них
подписано как Game Sound Type со значениями вида weapon_shooting, NPC_step,
item_dropping — это те же биты ESoundTypes.

**Звук без комментария: дефолты конструктора** (источник:
`src/xrSound/SoundRender_Source.cpp`, `CSoundRender_Source::CSoundRender_Source`):
`m_fMinDist = 1`, `m_fMaxDist = 300`, `m_fMaxAIDist = 300`, `m_fBaseVolume = 1`,
**`m_uGameType = 0`**. Следствие: у звука без валидного ogg-комментария аудио
работает (игрок слышит в пределах 300 м), но Event_Propagade его ИИ не рассылает
никогда (`g_type == 0`, раздел 4.1) — до npc_on_hear_callback такие звуки
НЕ доходят. Это главный источник «паковых» дыр: пересобранные/конвертированные
звуки модпаков без комментариев игрок слышит, а моды — нет. Симптом проверяется
на сборке с `-dbg`: в лог пишется «Missing ogg-comment, file: …».

## 4. Модель громкости в движке

### 4.1. Слух ИИ: как рождается событие звука

Источник: `src/xrEngine/IGame_Level.cpp`, `SoundEvent_Register`. Каждый
играющий звук периодически рассылается слушателям: движок запрашивает все
объекты-слушатели (spatial-тип `STYPE_REACTTOSOUND`) в кубе вокруг звука с
полустороной `range` и для каждого считает громкость события:

```
Power  = (1 - dist / max_ai_distance) * volume
Power *= occlusion
```

где `dist` — расстояние от звука до слушателя, `volume` — текущая громкость
звука, `occlusion` — глушимость между источником и слушателем
(`Sound::get_occlusion_to`, SOM-геометрия). Слушатели дальше `max_ai_distance`
отсеиваются ещё до формулы; события с `Power` ниже EPS отбрасываются. Радиус
запроса: `range = min(max_ai_distance, max_ai_distance * volume)` — тихий звук
(volume < 1) ИИ слышит на пропорционально меньшем расстоянии. Ограничение range
сверху: 500 м.

Окклюзия в этой формуле (источник: `src/xrSound/SoundRender_Core_Processor.cpp`,
`CSoundRender_Core::get_occlusion_to`) — один случайный луч: стартовая точка
берётся рядом с источником (случайное смещение в пределах `dispersion`),
направление — на слушателя; проверяется только SOM-геометрия уровня
(`geom_SOM`). Итог — произведение коэффициентов всех пересечённых
SOM-треугольников (коэффициент лежит в dummy треугольника); если SOM нет или
луч ничего не задел — окклюзия 1.0. Level-геометрия в ИИ-пути не участвует.
Практические выводы: power у одного и того же слушателя может «дрожать» от
замера к замеру (луч случайный), а препятствия, не размеченные SOM, слух ИИ
не глушат вовсе.

Источник: `src/xrSound/SoundRender_Emitter.cpp`, `Event_Propagade`. Рассылка
происходит только если у звука задан game_type (`g_type != 0`) и привязан
игровой объект (`g_object != 0`); период повторной рассылки играющего звука —
`s_f_def_event_pulse = 0.5` с (SoundRender.h). Следствие: зацикленные и длинные
звуки (гул зоны, стрельба очередями) продолжают «заявлять о себе» каждые
полсекунды, а короткий одиночный выстрел — один раз.

### 4.2. Слух игрока: аудио-модель

Источник: `src/xrSound/SoundRender_Emitter_FSM.cpp`, `update_culling`. Для
слушателя-игрока движок считает итоговую громкость так: если
`dist > max_distance` — звук замолкает (cull); иначе громкость линейно падает
от `min_distance` до `max_distance`:

```
volume_att = (max_distance - dist) / (max_distance - min_distance)  -- clamp 0..volume
```

`smooth_volume = base_volume * volume_att *` мастер-громкость
эффектов/музыки `* occluder_volume` (глушимость между звуком и игроком; для
`world_ambient` принудительно 1.0) `* fade_volume`. Ниже порога `psSoundCull`
звук выкидывается из микса. Итого обе модели — ИИ и аудио — линейны по
расстоянию, но с разными пределами: у ИИ — `max_ai_distance` из комментария,
у аудио — `max_distance`.

Детали реализации (SoundRender_Emitter_FSM.cpp, `update_culling`): для 2D-звуков
`occluder_volume = 1`, `volume_att = volume` — аттенюация по расстоянию и
окклюзия не применяются; `fade_volume` движется к 0/1 со скоростью 10/с;
`occluder_volume` плавно следует за окклюзией (lerp со скоростью 1/с) — звук
за стеной «притухает» не мгновенно. В аудио-пути окклюзия считается
`CSoundRender_Core::get_occlusion` (SoundRender_Core_Processor.cpp): луч от
слушателя к источнику (случайный сдвиг в радиусе 0.2 м); попадание в
level-геометрию даёт множитель `psSoundOcclusionScale` (0.5), затем
произведение коэффициентов SOM-треугольников вдоль луча; для `world_ambient`
окклюзия принудительно 1.0.

**Глобальные переменные звукового рендера** (источник:
`src/xrSound/SoundRender_Core.cpp`, Monolith): `psSoundTargets = 1024` (лимит
одновременно звучащих звуков, в оригинале был 32), `psSoundCull = 0.01`,
`psSoundOcclusionScale = 0.5`, `psSoundRolloff = 0.75`,
`psSoundVEffects = psSoundVFactor = psSoundVMusic = 1.0`, кэш 256 МБ.
Monolith-специфика: `psSoundMaxDistanceMultiplier = 1.0` и
`psSoundMaxAIDistanceMultiplier = 1.0` — глобальные множители обеих
дальностей; применяются при старте эмиттера:
`p_source.max_ai_distance = m_fMaxAIDist * psSoundMaxAIDistanceMultiplier`
(SoundRender_Emitter_StartStop.cpp). Консольные команды
(src/xrGame/console_commands.cpp): `snd_max_distance_multiplier` (0.2..2.0),
`snd_max_ai_distance_multiplier` (0.2..2.0). Влияние на Sound Vision: эти две
команды сдвигают ВСЕ радиусы слышимости сразу — удобный инструмент проверки
модели на тестах.

### 4.3. Кто и что доходит до Lua

Источник: `src/xrGame/sound_memory_manager.cpp`, `feel_sound_new`. Сначала
вызывается скриптовый колбэк звука (`m_object->sound_callback`) — ДО любых
порогов восприятия ИИ, т.е. колбэк получает все события в радиусе, даже слабые.
Только после этого применяются факторы класса (`weapon`, `item`, `npc`,
`anomaly`, `world` — имена в LTX именно такие, см. 4.4) и адаптивный порог
`m_sound_threshold` (затухает со временем к `m_min_sound_threshold`) — они
влияют лишь на память ИИ, не на колбэк.

Актёр (игрок) слушателем в Lua не отчитывается: `src/xrGame/Actor_Feel.cpp` —
`CActor::feel_sound_new` только запоминает собственный шум `m_snd_noise` (когда
источник — сам игрок). Поэтому моды «слышат» мир исключительно через уши NPC и
мутантов.

### 4.4. Порог восприятия и память ИИ

Источник: `src/xrGame/sound_memory_manager.cpp` (`CSoundMemoryManager`).
Точная последовательность `feel_sound_new`: (1) скриптовый колбэк звука;
(2) `update_sound_threshold()` — распад порога со времени прошлого звука;
(3) домножение power на факторы класса; (4) если `power >= m_sound_threshold`
— запись в память; (5) `m_sound_threshold = max(m_sound_threshold, power)`.
Параметры читаются из секции существа (`reload()`); имена в LTX — без
суффикса «_factor»:

**Таблица 4.1. Параметры слуха существа и дефолты движка**

| Параметр LTX | Дефолт | Смысл |
|---|---|---|
| `sound_threshold` | 0.05 | минимальный порог попадания звука в память |
| `DynamicSoundsCount` | 1 | ёмкость звуковой памяти (вытесняется старейшая запись) |
| `self_sound_factor` | 0.0 | множитель собственных звуков (0 — себя не «слышит») |
| `self_decrease_quant` | 250 мс | квант распада порога |
| `self_decrease_factor` | 0.95 | множитель распада за квант |
| `sound_perceive_section` | своя секция | секция, откуда читать факторы класса |
| `weapon` | 10.0 | фактор звуков класса WEAPON |
| `item` / `npc` / `anomaly` / `world` | 1.0 | факторы остальных классов |

Распад порога: `t = max(t · 0.95^(Δt/250 мс), 0.05)` — это ×0.81 в секунду;
с 1.0 до 0.05 порог падает ≈14.6 с, с 0.5 — ≈11.2 с, с 0.24 — ≈7.6 с. Шаг (5)
— «привыкание к шуму»: после громкого звука порог поднимается до его
громкости, и более тихие события не попадают в память, пока порог не
распадётся. Факторы класса и порог влияют только на память ИИ — на скриптовый
колбэк нет.

Особенности записи в память (`add()`): собственные звуки и звуки своих
предметов не запоминаются; звуки друзей и их предметов — тоже; источники,
видимые прямо сейчас, в звуковую память не попадают (звук ценен, когда врага
не видно); выстрел живого чужака (`WEAPON_SHOOTING` от чужой команды) вдобавок
кладётся в память попаданий как фейковый hit. В базовых конфигах Anomaly
1.5.x параметры слуха существами не переопределяются — работают дефолты
движка (проверено поиском по дампу: `sound_threshold` встречается только в
ltx психо-зон — sarcofag, underpass, agroprom_underground;
`sound_perceive_section` и `DynamicSoundsCount` не встречаются вовсе).

## 5. Типы звуков (ESoundTypes)

Источник: `src/xrServerEntities/ai_sounds.h` и экспорт в Lua (snd_type,
lua_help.script). Тип — битовая маска: старший бит задаёт класс
(оружие/предмет/монстр/аномалия/мир), младшие — характер звука.
Комбинированные значения заданы в заголовке явно (например,
`SOUND_TYPE_MONSTER_STEP = MONSTER | STEP`).

**Таблица 5.1. Биты классов и характеров звука**

| Бит | Значение | Смысл |
|---|---|---|
| WEAPON | 0x80000000 | оружие (выстрелы, перезарядка, щелчки) |
| ITEM | 0x40000000 | предметы (подбор, бросок, прятание) |
| MONSTER | 0x20000000 | мутанты (шаги, атаки, речь, смерть) |
| ANOMALY | 0x10000000 | аномалии (SOUND_TYPE_ANOMALY_IDLE = ANOMALY \| IDLE) |
| WORLD | 0x08000000 | мир: collide/break/explode/ambient |
| STEP | 0x00008000 | шаги (в паре с классом: MONSTER \| STEP) |
| TALKING | 0x00004000 | речь |
| SHOOTING | 0x00200000 | выстрел (WEAPON \| SHOOTING) |
| EMPTY_CLICKING | 0x00100000 | пустой щелчок |
| BULLET_HIT | 0x00080000 | попадание пули |
| RECHARGING | 0x00040000 | перезарядка |
| DYING / INJURING | 0x00020000 / 0x00010000 | смерть / ранение |
| ATTACKING / EATING | 0x00002000 / 0x00001000 | атака / поедание |
| IDLE | 0x00000800 | простой (гул аномалии) |
| OBJECT_BREAKING / COLLIDING / EXPLODING | 0x00000400 / 0x00000200 / 0x00000100 | поломка / столкновение / взрыв |
| PICKING_UP / DROPPING | 0x04000000 / 0x02000000 | подбор / бросок предмета |
| HIDING / TAKING / USING | 0x01000000 / 0x00800000 / 0x00400000 | спрятать / достать / использовать |
| AMBIENT | 0x00000080 | эмбиент |

Для скриптов важны константы `snd_type.*` из lua_help.script — это те же биты
enum: `snd_type.weapon = -2147483648` (старший бит знаковый в Lua),
`snd_type.weapon_shoot = -2145386496`, `snd_type.monster_step = 536903680` и
т.д. Проверка типа в Lua — битовая:
`bit_and(sound_type, snd_type.monster_step) == snd_type.monster_step`.
«Типы оружия» из заголовка (WEAPON_PISTOL, WEAPON_GUN, WEAPON_SUBMACHINEGUN,
WEAPON_MACHINEGUN, WEAPON_SNIPERRIFLE, WEAPON_GRENADELAUNCHER,
WEAPON_ROCKETLAUNCHER) равны простому WEAPON — по звуку движок не различает
класс оружия.

## 6. Lua API: sound_object и xr_sound

**sound_object** — скриптовый звук. Создаётся по пути без расширения:
`sound_object([[material\human\step\n_earth_01]])`. Флаги:
`sound_object.s3d = 0` (3D), `sound_object.s2d = 2` (2D «в голове»),
`sound_object.looped = 1`. Основные методы: `play(obj[, delay[, flags]])`,
`play_at_pos(obj, pos[, delay[, flags]])`,
`play_no_feedback(obj, flags, delay, pos, volume[, frequency])`, `stop()`,
`stop_deffered()`, `playing()`, `length()`; свойства `volume`, `frequency`,
`min_distance`, `max_distance`, `set_position`.

Важно: свойства громкости и дальностей читаются/меняются только у собственных
sound_object. Для движковых звуков (выстрелы, шаги, речь NPC) прочитать их
параметры из Lua нельзя — см. раздел 10. `play_no_feedback` создаёт эмиттер без
связи с исходным ref_sound и, что критично, шаги сталкеров играются именно так
(раздел 8).

**xr_sound** — обвязка схем: `get_safe_sound_object(path)` (безопасное
создание), `get_sound_object(theme, mode)`, `set_sound_play(id, theme, ...)`
для проигрывания реплик по sound-схемам; темы описываются в xml-конфигах схем
(sound_schemes).

**Чтение состояния чужого оружия из Lua** (экспорты CScriptGameObject,
источник: `src/xrGame/script_game_object_script2.cpp`,
`script_game_object_script3.cpp`) — обходной путь для детекции стрельбы, когда
звуковые события недоступны:

| Метод | Что даёт |
|---|---|
| `obj:best_weapon()` | предмет «лучшего оружия» сталкера (только CScriptEntity; script_game_object2.cpp:82) |
| `wpn:get_ammo_in_magazine()` | патроны в магазине (CWeapon::GetAmmoElapsed) |
| `wpn:get_ammo_total() / get_ammo_type()` | запас патронов / тип (GetSuitableAmmoTotal / GetAmmoType) |
| `wpn:get_state()` | состояние CWeapon: eFire = 5, eFire2 = 6, **eReload = 7** (eLastBaseState = 4) |
| `wpn:weapon_silencer_status()` | 0 — нет, 1 — съёмный, 2 — интегрированный (get_SilencerStatus) |
| `wpn:weapon_is_silencer()` | глушитель реально пристёгнут (Weapon_IsSilencerAttached) |

## 7. Колбэки звука

### 7.1. npc_on_hear_callback — главная точка входа

Полная цепочка (все звенья проверены по исходникам): движок →
`CScriptEntity::sound_callback` (буферизация) →
`CScriptEntity::process_sound_callbacks` → колбэк `GameObject::eSound` →
motivator_binder:hear_callback / generic_object_binder:hear_callback
(xr_motivator.script и bind_monster.script: пропускают мёртвых слушателей и
самозвуки) → xr_hear.hear_callback →
`SendScriptCallback("npc_on_hear_callback", ...)`. Слушателями выступают все
сталкеры (xr_motivator) и мутанты (bind_monster).

Реальная сигнатура (по xr_hear.script):

```lua
npc_on_hear_callback(npc, who_id, s_type, sound_dist, sound_power, sound_position)
```

Код прохода в xr_hear.script (проверен целиком): мотиватор вызывает
`xr_hear.hear_callback(obj, who_id, sound_type, sound_position, sound_power)`;
внутри вычисляется `sound_dist = sound_position:distance_to_sqr(obj:position())`
(отсюда и квадрат) и строка типа, после чего событие уходит скриптам:

```lua
SendScriptCallback("npc_on_hear_callback", obj, who_id, s_type, sound_dist,
                   sound_power, sound_position)
```

Механика on_sound (xr_hear.script, `reset_hear_callback` + `hear_callback`):
строки `on_sound`, `on_sound0`…`on_soundN` в секции схемы разбираются как
`<story_id>|<s_type>|<dist>|<power>|<condlist>`; условие срабатывания —
`dist >= линейная дистанция до источника И power >= порог` (dist здесь НЕ
квадрат — сравнение с `position:distance_to`), затем condlist через
`xr_logic.pick_section_from_condlist` и `switch_to_section`. Ключ выборки —
story_id источника (`get_object_story_id(who_id)`), при этом fallback на
`any` в коде отсутствует: `any` совпадает только с источниками, у которых
story_id нет вовсе. Это живой образец того, как сама игра фильтрует события
по громкости.

### 7.1.1. sound_position у оружия — это пуля, а не стрелок (проверено на GAMMA)

Кто есть кто в колбэке: `npc` — слушатель, `who_id` — **объект-источник** звука
(свои звуки актёра приходят, когда их слышит кто-то из NPC: `who_id == id
игрока`). А вот `sound_position` — точка, куда движок приложил событие, и для
оружейных типов она у стрелка бывает лишь случайно.

Эксперимент (GAMMA, ближний бой 2–3 сталкеров, отладочный журнал Sound Vision;
все 11 строк [HEAR] воспроизведены моделью громкости с точностью до третьего
знака — трактовка параметров подтверждена):

- пули, летевшие в игрока: `pos` в 1.7–3.5 м **от игрока** (точка попадания у
  укрытия), при стрелке в ~23 м;
- промахи: `pos` в 79–85 м **за игроком** — снаряды улетели дальше по линии
  огня; `sound_dist` (слушатель↔пуля) при этом 19.5–20.4 м;
- повторные импульсы того же звука (каждые 0.5 с) несут те же `sound_dist`/
  `sound_power` — звук живёт в памяти слуха, пока не затухнет;
- `WPN_shoot` от стволов пака с битыми ogg-комментариями не пришёл ни разу
  (`game_type = 0`, движок не рассылает — раздел 4.1): в канале слуха были
  только `WPN_hit` — звуки попаданий движок генерирует сам, и они доходят
  всегда, независимо от метаданных пакета;
- проверка «может, `who_id` — слушатель?» через неравенство треугольника:
  звук в 84.7 м от игрока не может находиться в 19.5 м от NPC, который сам
  в ~23 м от игрока (минимум 61.7 м); близкое событие нарушает тоже (19.2 <
  19.5). Единственная непротиворечивая трактовка — `who_id` = источник,
  что совпадает с кодом xr_hear.

Вывод для потребителей колбэка: позицию выстрела брать из **живой позиции
объекта-источника** (`level.object_by_id(who_id):position()`), а не из
`sound_position`; громкость пересчитывать до стрелка: `loud = power · (dl/dp)²`,
где dp — игрок↔стрелок (в том же логе: 0.013 → 0.175, выше порога 0.02).
Для шагов, голосов и зон `sound_position` совпадает с источником — там разницы
нет. Взрывы/гранаты (строки без префикса `WPN_`) лучше держать в точке
`sound_position` — там полезна точка взрыва, а не бросавший.

Стабильность (Sound Vision v2.4): при переносе события замер громкости теряет
физический смысл — `sound_power` мерился у слушателя ПУЛИ, а `dl` — расстояние
до пули, не до стрелка. Один и тот же выстрел (стрелок в 23 м от игрока) давал
после переноса loud = 0.010 у слушателя в 3 м от пули (ниже порога), 0.170 у
слушателя в 19 м, 0.378 у слушателя в 50 м — метка «моргала» в зависимости от
того, кто услышал пулю. Перенесённым событиям нужна громкость от **якоря типа
звука** (виртуальный якорь {d_v, p_v}, единая модель с опросом мира), а не от
замера слушателя: выстрел 0.60@45 м (с глушителем 0.30@20 м), перезарядка
0.22@12 м, сухой щелчок 0.15@8 м.

Входящий огонь (Sound Vision v2.5): у якорной громкости есть слепая зона —
стрелок далеко за пределами слышимости выстрела, а его ПУЛИ крошат землю рядом
с игроком (вертолёт в 300–550 м, попадания в 7–25 м). Якорь стрелка отвергает
такое событие (0.004 < порога), и игрок без единой метки. Для WPN_* считаются
оба кандидата — стрелок (якорь типа звука) и точка попадания (перенос замера
у ИИ-слушателя на игрока: `loud = power · (dl/d_en)²`, где d_en — игрок↔пуля);
кольцо получает слышимый. Техника в канале слуха опознаётся по who_id: у
вертолётов Anomaly секция/имя объекта — секция отряда `simulation_helicopter_*`.
Ещё нюанс: обращение к методам сталкера (`active_item`) на game object техники
бросает ошибку биндинга, которая печатается в лог даже под `pcall` — методы
щупать только после `IsStalker(obj)`.

Выстрел живёт у ствола (Sound Vision v2.6): у правила «кто слышнее» была дыра —
оно запускалось только при расхождении точки пули со стрелком больше 2 м, а
когда пуля ещё у ствола, событие уходило в перенос замера. Перенос от
слушателя, стоящего ВПЛОТНУЮ к источнику, недостоверен в принципе: движковый
`sound_power` линейный и насыщается у единицы (`p ≈ 0.98` уже в 3 м), поэтому
`0.98·(3/43)² ≈ 0.004` — на четыре порядка ниже реальной громкости выстрела у
игрока (бой 05.11: `rejected loud=0.0039/0.0046 d=42–44 м` при видимом
стреляющем). Вывод: `WPN_shoot` — сам звук выстрела, излучается у дульного
среза — якорить к стрелку ВСЕГДА, без сравнения с пулей; сравнение оставить
только `WPN_hit` (там точка движка — попадание). И держать кап очереди
согласованным с якорем: якорь выстрела слышен до 45·√(0.60/0.02) = 246 м,
общий кап 150 м резал «слышимое» — для weapon поднят до 250 м.

Движковый факт → кольцо (Sound Vision v2.7): «слышимость как в игре» по порогу
действует только на события ОПРОСА мира (там громкость — наша модель). Всё,
что движок сам донёс до Lua (канал слуха `npc_on_hear_callback`: звук прошёл
ИИ-фильтр дистанции и глухости стен; канал выстрелов
`npc_on_weapon_shot_start`: выстрел случился по факту), доступность-мод
показывает ВСЕГДА — порог к движковым фактам не применяется. Антиспам на
weapon тоже не действует: копии одного звука от разных ИИ-слушателей
(в логе это повторные `WPN_hit` с разными `dl` от одного `who_id`) склеиваются
в одно живое кольцо стрелка. Красные метки защищены и от вытеснения из
очереди: при переполнении FIFO жертвует самым старым НЕ-weapon событием
(шаги/физика/гул зон) — иначе поток фоновых колец боя вытеснял метки выстрелов
раньше их жизни (симуляция: 62–84% weapon-колец вытеснялось, кольцо видно
лишь 32–38% времени стрельбы).

### 7.4. Взрывы: как звучат и как их ловить (v2.9)

Где задаются. Звук взрыва читается движком из параметра `snd_explode`

"sndExplode", ..., m_eSoundExplode)`). У ручных гранат Anomaly строка сидит не в
секции самой гранаты, а в её звуковой базе (`weapon_sounds.ltx`:
`[grenade_f1_sounds]: base_sounds → snd_explode = grenade_f1_snd_explode`; у
подствольных — в базах оружия: `snd_explode = wpn_fake_vog-25_explode`);
у взрывчатки (`explosive_barrel`, класс `S_EXPLO`) — в секции предмета.

Как взрыв доходит до Lua. `m_eSoundExplode = ESoundTypes(SOUND_TYPE_WEAPON_
SHOOTING)` (`Explosive.cpp:59`): ИИ-рассылка взрыва несёт маску
WEAPON\|SHOOTING → в `npc_on_hear_callback` это строка `WPN_shoot`,
неотличимая от выстрела. Отличить можно только по источнику `who_id`: у
выстрела — сталкер, у взрыва — неживой объект (граната, снаряд подствольника,
бочка, мина, ракета). Каналы ловли (проверено по исходникам, v2.9):

| Канал | Что ловит | Сборки | Замечания |
|---|---|---|---|
| слух: `WPN_shoot` от неживого объекта-не-зоны | всё, что играется движком, с честной громкостью у слушателя | любые | нужен ИИ-слушатель в радиусе; актёр в Lua слух не отчитывает |
| опрос полёта гранаты | ручные гранаты + подствольные снаряды | любые, чистый Lua | независим от слушателей и ogg-метаданных |
| `explosive_item_on_explode` | бочки, мины, взрывчатка (`CExplosiveItem`) | только modded exes | в ванильном 1.5.x НЕТ (проверено клоном anomalymod/xray-monolith); `SendScriptCallback("explosive_item_on_explode", obj)` — один аргумент, `gamedata/scripts/callbacks_gameobject.script:583` |
| hit-колбэки (`actor_on_before_hit`, hit_type explosion) | взрывы, задевшие игрока/NPC | modded exes | грубый запасной канал, Sound Vision не использует |
| таймер «бросок + fuse» | ручные гранаты | любые | требует каллибровки fuse на каждый пак, не использует |

Опрос полёта гранаты — механика (`src/xrGame/Missile.cpp`): `spawn_fake_missile`
(строка 176) спавнит фейковый снаряд по `cNameSect()` — секция летящей гранаты
равна секции предмета (`grenade_f1`, `grenade_rgd5`, `grenade_gd-05`); подствольный
снаряд — `[gl_fake_missile_ammo_vog-25]: wpn_fake_missile, gl_fake_missile`
(база `wpn_fake_missile`, класс `G_FAKE`, base.ltx:207). Пока снаряд в предмете/в
стволе — он запарентчен (`GE_OWNERSHIP_TAKE`); бросок — `GE_OWNERSHIP_REJECT`,
в полёте `parent() == nil`. Взрыв уничтожает `CGrenade` → исчезновение из
`db.storage` и есть момент взрыва; подбор объект не уничтожает (меняется
родитель). Классы: `clsid.wpn_grenade_f1_s = 77`, `clsid.wpn_grenade_rgd5_s =
82`, `clsid.wpn_grenade_fake = 78` (lua_help.script) — Sound Vision строит
набор из всех ключей `clsid` с префиксом `wpn_grenade`. Дым/газ без взрывного
урона отсекается по `hit_type_blast ~= "explosion"` в ini (`m_gsmoke`:
`strike, blast = 0`; у F1/RGD5/GD5 — `explosion`).

Громкость и размер. Честная громкость взрыва у игрока — перенос замера
ИИ-слушателя обратным квадратом (как у всех слуховых событий). Для опроса и
колбэка громкости нет — виртуальный якорь `ANV_EXPL = {25, 0.80}` (взрыв
слышен до ~100 м). Опция «Крупные ореолы взрывов» (v2.9, включена по
умолчанию): кольцо взрыва не уменьшается с расстоянием (базовый размер
полный), а громкость добавляет размер `scale = 1 + громкость` (до 2х) —
громкий взрыв бочки/ракеты крупнее далёкой гранаты. Порог слышимости на
взрывы не действует (дискретный факт, как выстрел), потолок дальности 200 м,
защита от вытеснения — как у weapon. Ключ антиспама — числовой `id`
объекта-взрыва, общий для всех трёх каналов: копии склеиваются, дублей нет.
Синие «физические» кольца ударной волны в точке свежего взрыва сливаются с ним
(окно 0.9 с, радиус 7 м).

## 8. Как устроены шаги

Источник: `src/xrGame/step_manager.cpp`. Шаги привязаны к анимациям: в конфиге
персонажа секция `step_params` перечисляет анимации движения; для каждой —
число циклов и на каждую ногу время и power (0..1) шага в цикле. При наступании
движок берёт пару материалов под ногой, играет случайный звук из StepSounds
пары и передаёт power дальше.

Ключевые факты: аудио шагов играется только в пределах
`g_step_sound_distance = 50` м от камеры (дальше — тишина, партиклы тоже
отключаются по `g_step_particle_distance = 50`; обе выведены в консоль —
команды `step_sound_distance` и `step_particle_distance`, допустимо
10..100); у актёра перед проигрыванием
вызывается Lua-функция `CActor__FootstepCallback(имя_материала, power,
hud_mode)` — тот самый actor_on_footstep; у NPC вызывается C++
`FootStepCallback(power, b_play_sound, is_on_ground, hud_mode)`. В hud-режиме
звук шага 2D с громкостью `power * psHUDStepSoundVolume`, в мире — 3D.

Шаги NPC играются через `play_no_feedback`: тип звука не задаётся, поэтому
Event_Propagade их не рассылает ИИ (`g_type == 0`) — до npc_on_hear_callback
шаги сталкеров НЕ доходят. Шаги мутантов доходят (MST_step): мутанты играют их
как обычные типизированные звуки. Для сталкеров единственный надёжный источник
— опрос мира по движению (так делает Sound Vision) либо modded exes.

Константы громкости из `src/xrServerEntities/ai_sounds.h`:
`CROUCH_SOUND_FACTOR = 0.3` и `ACCELERATED_SOUND_FACTOR = 0.5` — движковые
множители тихого и ускоренного движения; применяются при подсчёте
воспринимаемого шума персонажа. Практический вывод: крадущийся NPC втрое
«тише» идущего, ускоряющийся — вдвое громче.

## 9. Практические паттерны

### 9.1. Модель слышимости Sound Vision (якорь ИИ + обратный квадрат)

Задача: показывать кольцо только если игрок слышит звук, без калибровки каждого
.ogg. Решение v2.0: каждое событие npc_on_hear_callback — это «замер громкости»
чужим ухом. Громкость у игрока восстанавливается децибельной моделью
расхождения фронта (−6 дБ на удвоение расстояния):

```
loud = power * (dl / dp)^2    -- dl: дистанция ИИ-слушателя, dp: игрока
```

Показывать, если `loud >= порог` (MCM, по умолчанию 0.02) и `dp <= 150` м.

Свойства модели: если игрок ближе слушателя — громкость у него не меньше,
событие показывается всегда; стены уже «вшиты» в power (occlusion) и
дополнительно уменьшают loud; за пределами слуха ИИ событий не существует
вовсе, поэтому дальнее поле не спамит. Численный прогон (симуляция при пороге
0.02): выстрел из автомата виден до ~150 м (предел показа), крик — до ~80 м,
шаги бегущего — ~35 м, идущего — ~29 м, крадущегося — ~25 м, толкание бочки —
~20 м.

Источники без движковых данных (шаги сталкеров, физика, гул зон) несут
громкость от «виртуальных якорей»: константа `{d_v, p_v}` — на d_v метрах
громкость p_v, дальше тот же обратный квадрат. Шаги: p_v растёт со скоростью
движения, измеренной между опросами (крадущийся 0.10, бегущий 0.24 на якоре
10 м). Это 4 числа на все опрошенные источники — не калибровка каждого звука.

### 9.2. Слой поверх шагов актёра

```lua
local function actor_on_footstep(surface, power, is_crouching, flags)
    local vol = power * (is_crouching and 0.3 or 1.0)  -- как CROUCH_SOUND_FACTOR
    local snd = xr_sound.get_safe_sound_object("my_foley\\cloth_" .. math.random(1, 8))
    if snd then
        snd:play_no_feedback(db.actor, sound_object.s2d, 0, vector(), vol)
    end
end
RegisterScriptCallback("actor_on_footstep", actor_on_footstep)
```

### 9.3. Что читать, когда нужно «поймать» событие

Оружие и монстры — npc_on_hear_callback (типы `WPN_*`, `MST_*`): движок сам
отдаёт громкость и позицию. Собственные шаги игрока — actor_on_footstep
(surface, power). Движение/физика без ИИ-событий — только опрос (db.storage,
сравнение позиций по таймеру 4 Гц, как в sound_vision_detect.script). Аномалии
— anomaly_on_before_activate и actor_on_feeling_anomaly. Удары по объектам —
physic_object_on_hit_callback (amount пригоден как прокси громкости).

## 10. Ограничения и подводные камни

Проверено по исходникам:

1. из Lua нельзя прочитать параметры чужих звуков — base_volume, max_distance,
   max_ai_distance доступны только для собственных sound_object;
2. актёр не получает npc_on_hear_callback как слушатель — «слух игрока»
   недоступен напрямую, только через уши NPC;
3. шаги сталкеров не рассылаются ИИ (play_no_feedback, g_type = 0) — ловить
   движением;
4. sound_dist в колбэке — квадрат расстояния, не забывать корень;
5. рассылка повторяется каждые ~0.5 с — нужен антиспам;
6. 2D-звуки приходят с позицией камеры;
7. окклюзия ИИ считается по одному случайному лучу — power у слушателя может
   отличаться от рассылки к рассылке;
8. звуки классов WORLD/ANOMALY (гул аномалий, эмбиент) приходят в колбэк как
   NIL; взрывы — НЕТ: snd_explode играется с маской WEAPON_SHOOTING
   (Explosive.cpp:59) и приходит строкой WPN_shoot — см. 7.4;
9. линии видимости из Lua нет «из коробки», но в Monolith (Anomaly 1.5.2+,
   `src/xrGame/level_script.cpp`, «KD: raypick») экспортированы лучи уровня:
   свободная функция `level.ray_pick(from, dir, range, rq_target, rq_result,
   ignore_object)` (истина + заполненный `rq_result`, поле `.range` — дистанция
   попадания) и класс `ray_pick` (CRayPick: constructor(from, dir, range,
   rq_target, ignore) + `query()`/`get_distance()`); цель луча —
   `rq_target.rqtStatic` (статическая геометрия), `rqtBoth` добавляет
   динамические объекты. На сборках без этого биндинга (старые экзешники)
   обращение под pcall — Sound Vision v2.8 пробует `level.ray_pick`, затем
   класс, и при неудате отключает учёт перекрытия с честной строкой OCC в журнале;
   закрытые двери — динамическая геометрия: `rqtStatic` их не видит.

Из практики сообщества (экспериментально, не из исходников): глобального
«on_any_sound_played» нет; громкость многослойных звуков оружия правится только
заменой .ogg или sound_layers в LTX; sound_object нельзя создавать каждый кадр
— кэшировать; слух ИИ настраивается факторами класса в ltx (`weapon`, `item`,
… — раздел 4.4), что влияет на память ИИ, но не на колбэк.
